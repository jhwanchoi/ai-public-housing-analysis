# 공고 원문 확보와 대조

## 브라우저 사전 점검

SH 첨부파일, LH청약플러스 공고문처럼 **브라우저로만 열리는 원문**이 하나라도 있으면, 읽기 전에 브라우저 도구(Claude in Chrome)가 연결돼 있는지 먼저 확인한다. 사이트별로 무엇이 막히는지는 `references/site-access.md`를 본다.

- 연결돼 있지 않으면 분석을 시작하기 전에 사용자에게 알린다.
  > "SH와 LH 공고 원문은 브라우저로만 열려서 Chrome이 필요합니다. Chrome을 켜고 Claude 확장을 연결해 주시면 바로 확인하겠습니다."
- 사용자가 켜지 않기로 하면, 브라우저 없이 확인할 수 있는 공고만 진행하고 나머지는 이유를 붙여 "원문 미확인"으로 남긴다.

## 원문 찾기

1. 받은 링크가 블로그나 요약 사이트라면 **공식 출처까지 거슬러 올라간다.**
   - SH: i-sh.co.kr 공고 게시판, 서울주거포털(housing.seoul.go.kr)
   - LH: LH청약플러스(apply.lh.or.kr)
   - HUG 든든전세: khug.or.kr/jeonse
   - 청년안심주택과 공공지원민간임대: 단지 공식 홈페이지, 서울시 청년안심주택 안내
   - 마이홈포털(myhome.go.kr): 보조 확인용
2. **판단은 공식 첨부 PDF로 한다.** 공고 페이지에 들어가 첨부파일 다운로드 링크(예: `fileDown.do?atchFileId=...`)를 찾고, 모집공고 PDF를 직접 받아 읽는다. 요약 사이트의 표는 빠지거나 틀린 칸이 있을 수 있으니 면적, 임대료, 물량, 일정을 옮겨 적지 않는다.
   - 예: 서울시 청년안심주택은 `soco.seoul.go.kr` 공고 상세 페이지 HTML에서 첨부 링크를 찾아 `curl`로 받을 수 있다.
3. 공식 사이트가 자동 조회를 막으면 브라우저 도구로 연다. SH는 첨부 "미리보기" 쪽 이미지, LH는 "바로보기" 문서 뷰어와 뷰어 검색으로 읽는다(`references/site-access.md`). 그래도 열리지 않으면 사용자에게 PDF를 요청한다.
4. 그래도 요약 사이트 정보밖에 없으면 **"요약 사이트 기준이며 공식 원문은 확인하지 못함"**이라고 밝히고, 판정은 조건부로 둔다.

## 반드시 확인할 것

- **정정, 변경, 취소 공고**: 공급 제외 호수, 임대조건 정정, 일정 변경. 원래 공고보다 우선한다.
- **문서 안의 모순**: 같은 PDF 안에서 접수 마감일이나 발표일이 다르면 공식 신청 화면의 일정을 따르고, 차이를 사용자에게 알린다.
- **"(안)" 표시가 붙은 파일**: 실제로 게시됐는지와 게시일을 확인한다.
- 이미 접수가 끝난 공고라면 그 사실부터 알리고, 어디까지 분석할지 사용자와 맞춘다.

## 파일 읽기

**읽는 순서**: 자격 판정에 필요한 쪽부터 본다. ① 대상 계층의 1인 소득 상한과 산정 자료(사회보장정보시스템, 원천징수영수증 등) → ② 자산, 차량 → ③ 공급 주택형과 임대조건 → ④ 공급일정. 소득 한 줄로 부적격이 정해지면 나머지는 읽지 않는다.

- PDF: `pdftotext -layout`로 텍스트를 뽑는다. 표, 평면도, 위치도처럼 배치가 중요한 쪽은 이미지로 렌더링해서 본다.
- HWPX: 압축을 풀어 `Contents/section*.xml`에서 텍스트를 뽑는다.
- XLSX와 XLS: 여러 줄일 수 있는 머리글 행부터 파악한 뒤 행 단위로 읽는다. 원본 파일은 고치지 않는다.
- 내려받은 파일은 별도 작업 폴더에 두고, 스크립트는 그 폴더 밖에서 실행한다.

- 신청 사이트와 문의처
