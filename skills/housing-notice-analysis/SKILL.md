# 주거·청약 공고 분석

## 0. 시작 전에

1. **사용자 프로필을 먼저 읽는다.** 경로는 `$HOUSING_PROFILE`, 없으면 작업 폴더의 `profile.md` 또는 `outputs/주거·청약-기본프로필.md`. 프로필이 없으면 `profile.example.md` 양식으로 필요한 항목을 질문한다.
2. 프로필에서 재사용하는 것은 **사용자 본인의 정보와 선호뿐**이다. 이전 공고의 순위, 금액, 경쟁률, 판단을 새 공고에 섞지 않는다.
3. 공고 원문(PDF·HWPX·XLSX)을 직접 읽는다. 블로그 요약은 공식 원문을 찾지 못했을 때만 보조로 쓰고, 그렇다고 밝힌다.
4. 파일명에 `(안)`이 있거나 PDF 안에서 일정이 서로 다르면 **공식 사이트 게시본과 대조**한다.

## 1. 자격 판정 (가장 먼저, 부적격이면 여기서 끝)

공고의 **공급유형별로** 따로 판정한다. 같은 공고라도 청년 특공과 일반공급의 소득표가 다를 수 있다.

확인 항목:
- 기준일(공고일), 연령은 공고일 기준 만 나이
- 혼인, 무주택(본인/세대), 세대 구성, 세대주 여부
- 거주지 요건과 지역우선(연속 거주기간)
- 소득: **상한 금액 + 산정 자료 + 산정 시점** → `references/income-rules.md`
- 자산(임차보증금 포함 여부), 자동차가액
- 부모 소득·자산 포함 여부와 부모 검증 범위
- 청약통장 요건, 가점 항목, 과거 당첨·재당첨제한

판정 규칙:
- **모든 신청 가능 경로가 막히면 사유와 공고 근거(쪽수·문구)만 쓰고 종료한다.** 주택 비교, 비용, 출퇴근 분석은 하지 않는다.
- 경계선이면 "가능"으로 단정하지 않는다. "○○ 자료가 반영되면 초과/충족"처럼 조건부로 쓰고, 확정에 필요한 확인 방법을 붙인다.
- 미확인 개인정보는 추정하지 않는다. 판정에 꼭 필요한 것만 짧게 묻는다.
- 소득 초과여도 **후순위로 신청 가능한 공고**가 있다(예: SH 장기미임대 2순위). 초과 = 부적격으로 바로 결론 내지 않는다.

## 2. 당첨 구조 파악

- **공급호수와 예비자 수를 구분**한다. 예비자는 입주 물량이 아니다.
- 선정 단계를 순서대로 쓴다(우선공급 → 가점 → 추첨 등). 사용자가 실제로 경쟁하는 단계와 그 단계의 물량을 계산한다.
- 미혼자 무주택기간은 만 30세부터 기산하는 등, 가점에서 불리한 지점을 짚는다.
- 접수 전이라 신청자 수를 모르면 "당첨확률 ○배" 같은 수치를 만들지 않는다.
- 호수 선택 방식(주택군 신청 후 순번 선택, 무작위 배정 등)과 그에 따른 평면·면적 편차를 설명한다.

## 3. 주택 평가

현재 집을 기준점으로 **좋아지는 점과 나빠지는 점을 둘 다** 쓴다.

비용 → `references/cost-formulas.md`
- 월세 + 관리비 + 추가 보증금의 금융비용으로 **실질 월 주거비**를 낸다.
- 보증금은 선호 상한으로 바로 탈락시키지 않는다. 추가 보증금 대비 월세 절감(전환수익률)을 계산한다.
- 관리비가 미확인이면 가정값과 함께 "가정"이라고 표시한다.

면적·평면
- 전용면적 기준으로 비교한다. 공급형 이름(예: "60~70㎡")이 실사용면적일 수 있으니 확인한다.
- 침실 분리 여부, 확장, 수납, 기본 옵션(인덕션 여부 포함)을 평면도로 확인한다.

출퇴근
- 직장까지 **실제 대중교통 경로**로, **평일 오전 8시 전후 출발**로 조회한다. 현재 집도 같은 조건으로 조회해 비교한다.
- 도착지가 역인지 회사 주소인지 표시한다. 기준이 다른 값을 빼서 비교하지 않는다.
- 조회하지 못했으면 "미검증"이라고 쓰고 추정값을 사실처럼 쓰지 않는다.

## 4. 추천

- 하나를 고를 때는 **가중치를 먼저 밝힌다.** 기본값은 프로필의 가중치, 없으면 아래.

  | 요소 | 기본 가중치 |
  |---|---:|
  | 출퇴근 | 30% |
  | 가격·실질 주거비 | 30% |
  | 당첨 가능성 | 20% |
  | 면적·평면 | 15% |
  | 건물·생활환경 | 5% |

- 사용자가 지금 집에 계속 살 수 있다면, "당첨 가능"이나 "공공이라 싸다"만으로 추천하지 않는다. 여러 요소가 함께 나아지는 후보를 우선한다.
- 사용자가 반박하면(예: "생각보다 비싼데?") 입장을 바꾸는 이유를 숫자로 보이고, 이전 추천을 명시적으로 철회하거나 유지한다.
- 결론을 요구하면 조건부 나열 대신 **하나로 답하고**, 결론이 바뀌는 조건만 덧붙인다.

## 5. 분양 상품 추가 체크

토지임대부·공공분양은 임대와 판단 축이 다르다.
- 재당첨제한, 전매제한, 거주의무, 공공매입(되파는 가격 규정)
- 토지 소유 여부, 토지임대료와 보증금 전환 가능 여부, 분양전환 여부
- 당첨 후 계약 포기 시 불이익 → "일단 넣어보기"가 가능한 공고인지 판단
- 계약금·잔금 시점과 현재 집 보증금 반환 시점

## 6. 일정 등록 (사용자가 요청하거나 지원을 결정했을 때)

공고당 **2개만** 등록한다.
1. **청약 접수 첫날** (마감일·시각은 메모에)
2. **그 신청에 대한 서류심사 대상자 발표일**, 발표 시각에 맞춰. 서류대상자 발표가 따로 없는 공고는 당첨자 발표일로 하고 메모에 그 사실을 적는다.

접수 첫날 메모에 넣을 것: 공고명·공고일, 신청 사이트, 공급유형·순위·주택형(주택군), 보증금·월세(또는 분양가), **사용자 자격 판정 요약**, 신청하면 안 되는 유형, 당첨 구조, 주의사항.

사용자가 메모 원문을 달라고 하면 캘린더 수정 대신 **복사 가능한 텍스트 블록**으로 준다.

## 7. 답변 형식

- 첫 문장에 결론(지원 가능/불가, 추천 여부).
- 자격 → 당첨 구조 → 비용 → 면적 → 출퇴근 → 추천 → 일정 순서.
- 금액·면적은 표로, 근거는 공고 쪽수와 함께.
- 확인된 사실, 가정, 미검증을 구분해서 쓴다.
- 새로 확인된 개인정보(소득 자료, 거주 시작일 등)는 확인일과 함께 프로필에 반영한다.
