# 공고 분석 진입점

## 개인 데이터 위치 (모든 housing-* skill 공통)

개인정보는 플러그인 저장소에 두지 않는다. 아래 순서로 찾는다.

1. `$HOUSING_DATA_DIR` (설정돼 있으면)
2. `~/.config/ai-public-housing-analysis/`
   - `profile.md`: 사용자 프로필 (소득 자료별 금액, 자산, 현재 집, 선호, 가중치, 운영 규칙)
   - `applications.md`: 신청 현황 (housing-tracker가 관리)
3. 없으면 플러그인의 `profile.example.md` 양식으로 필요한 항목만 질문하고 위 경로에 만든다.

프로필에서 재사용하는 것은 **사용자 본인 정보와 선호뿐**이다. 이전 공고의 순위·금액·경쟁률·판단을 새 공고에 섞지 않는다. 새로 확인된 개인정보는 확인일·출처와 함께 `profile.md`에 반영한다.

## 흐름

1. **원문 확보** → `housing-research`
   첨부 파일·링크·공고명에서 공식 원문, 정정공고, 공급목록, Q&A, 공식 일정을 확보한다.
2. **충돌 검사** → `housing-tracker`
   진행 중인 신청과 중복신청 제한이나 재당첨제한이 겹치는지 먼저 본다. 겹치면 결론 앞에 경고한다.
3. **자격 판정** → `housing-eligibility`
   **모든 신청 경로가 부적격이면 사유와 공고 근거만 쓰고 여기서 종료한다.** 이후 단계는 하지 않는다.
4. **후보 비교·추천** → `housing-unit-pick`
   당첨 구조, 실질 비용, 면적·평면, 출퇴근, 가중치 추천. 분양 상품은 분양 체크까지.
5. **결론**
   첫 문장에 지원 여부와 추천 주택군. 확인된 사실, 가정, 미검증을 구분한다.
6. **신청 실행**: 사용자가 요청하거나 지원을 결정하면 → `housing-apply`, 이어서 `housing-tracker`에 기록.

## 답변 형식

- 첫 문장: 결론(지원 가능/불가, 추천 여부).
- 자격 → 당첨 구조 → 비용 → 면적 → 출퇴근 → 추천 → 일정 순서.
- 금액·면적은 표로, 근거는 공고 쪽수와 함께.
- 사용자가 "하나만"이라고 하면 조건부 나열 대신 하나로 답하고, 결론이 바뀌는 조건만 덧붙인다.
