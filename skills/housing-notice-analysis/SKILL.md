# 공고 분석 진입점

이 플러그인의 판단은 참고용이다. 최종 자격과 순위는 공고 원문과 시행 기관의 심사로 정해진다는 점을 답변에서 분명히 한다.

## 개인 데이터 위치 (모든 housing-* skill 공통)

개인정보는 플러그인 저장소에 두지 않는다. 아래 순서로 찾는다.

1. `$HOUSING_DATA_DIR` (설정돼 있을 때)
2. `~/.config/ai-public-housing-analysis/`
   - `profile.md`: 사용자 프로필(자료별 소득, 자산, 현재 집, 선호, 가중치, 진행 방식)
   - `applications.md`: 신청 현황(housing-tracker가 관리)
3. 둘 다 없으면 플러그인의 `profile.example.md` 양식을 기준으로 필요한 항목만 묻고, 위 경로에 파일을 만든다.

프로필에서 다시 쓰는 것은 **사용자 본인의 정보와 선호뿐**이다. 이전 공고의 순위, 금액, 경쟁률, 판단을 새 공고에 섞지 않는다. 새로 확인한 개인정보는 확인 날짜와 출처를 붙여 `profile.md`에 반영한다.

## 진행 순서

1. **원문 확보** → `housing-research`
   첨부 파일, 링크, 공고명에서 공식 원문, 정정 공고, 공급 목록, Q&A, 공식 일정을 확보한다.
2. **충돌 검사** → `housing-tracker`
   진행 중인 신청과 중복신청 제한이나 재당첨 제한이 겹치는지 먼저 본다. 겹치면 결론보다 먼저 알린다.
3. **자격 판정** → `housing-eligibility`
   **모든 신청 경로가 막히면 사유와 공고 근거만 쓰고 여기서 끝낸다.** 다음 단계로 넘어가지 않는다.
4. **후보 비교와 추천** → `housing-unit-pick`
   당첨 구조, 실질 비용, 면적과 평면, 출퇴근, 가중치에 따른 추천. 분양 상품은 분양 점검 항목까지 본다.
5. **결론**
   첫 문장에 지원 여부와 추천 주택군을 쓴다. 확인한 사실, 가정, 검증하지 못한 내용을 구분한다.
6. **신청 실행**
   사용자가 요청하거나 지원을 정하면 `housing-apply`로 일정을 잡고 `housing-tracker`에 기록한다.

## 답변 형식

- 첫 문장에 결론(지원 가능 여부, 추천 여부)을 쓴다.
- 자격 → 당첨 구조 → 비용 → 면적 → 출퇴근 → 추천 → 일정 순서로 쓴다.
- 금액과 면적은 표로 정리하고, 근거에는 공고 쪽수를 붙인다.
- 사용자가 하나만 골라 달라고 하면 여러 조건을 늘어놓지 말고 하나로 답한다. 결론이 바뀌는 조건만 덧붙인다.
