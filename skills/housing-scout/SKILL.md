# 새 공고 찾기와 1차 선별

개인 데이터 위치는 `housing-notice-analysis`의 공통 규칙을 따른다.

## 찾아볼 곳

- **SH**: 공고 게시판, 서울주거포털의 공공임대와 공공분양 목록
- **LH**: LH청약플러스의 임대와 분양 공고(서울과 수도권 지역본부)
- **HUG 든든전세**: 공지사항, 모집공고 목록
- **청년안심주택**: 서울시 청년안심주택 모집공고와 단지 홈페이지
- **그 밖에**: 마이홈포털, 청약홈(공공분양, 토지임대부)

**브라우저 사전 점검**: SH와 LH청약플러스는 원문 첨부가 브라우저로만 열린다. 조사를 시작할 때 브라우저 도구(Claude in Chrome) 연결 상태를 확인하고, 연결돼 있지 않으면 **찾기 전에** 사용자에게 Chrome을 켜 달라고 안내한다(`housing-research`의 "브라우저 사전 점검"). 사용자가 켜지 않아도 찾기와 1차 선별은 계속한다.

사용자가 원하는 지역(예: 서울)이면서 접수 마감 전인 공고만 남긴다. `applications.md`에 이미 있는 공고는 상태만 표시하고 다시 분석하지 않는다.

요약 사이트와 검색 결과는 **공고를 찾는 용도로만** 쓴다. `신청 가능`이나 `조건부`로 남긴 공고는 `housing-research` 방식대로 공식 사이트에서 모집공고 PDF를 직접 받아 자격, 면적, 임대료를 확인한 뒤 판정한다. PDF를 아직 보지 못한 공고는 판정 옆에 "원문 미확인"과 **그 이유**를 붙인다.

- 예: "원문 미확인(Chrome 미연결로 SH 첨부를 열지 못함)", "원문 미확인(출퇴근 기준으로 후순위, 원문 열지 않음)"
- 원문을 열지 않고 넘긴 공고가 있으면 답변 마지막에 몇 건인지와 다음 행동을 쓴다. 예: "Chrome을 켜 주시면 이 3건을 바로 확인합니다."
- 출퇴근이나 지역 때문에 원문 확인을 건너뛰는 기준은 사용자 프로필의 선호(예: 핵심 목적지까지 허용 통근 시간)로만 정한다. 프로필에 기준이 없으면 건너뛰지 말고 확인하거나, 건너뛴 공고 목록을 보여 주고 확인할지 묻는다.

## 1차 선별 (공고당 간단히)

공고문 전체를 깊게 읽기 전에 **탈락 사유부터** 찾는다. 가장 빠른 길은 **대상 계층의 1인 소득 상한 한 줄**이다. 그 금액과 산정 자료(사회보장정보시스템, 원천징수영수증 등)를 먼저 찾아 사용자 값과 비교하고, 초과하면 다른 항목은 읽지 않는다. 단, 완화 공고는 순위별 소득표를 모두 본다(`housing-eligibility`).

1. 대상 계층: 청년, 신혼부부, 고령자, 일반 중 사용자가 해당하는지
2. 소득 제한이 있는지, 어떤 **소득표 기준**(본인 1인, 3인 이하, 부모 포함)인지. 사용자의 최신 소득 자료와 비교한다.
3. 자산과 차량 상한
4. 면적과 유형: 사용자가 신청할 수 있는 주택형이 현재 집보다 넓은지
5. 지역 우선, 무주택기간처럼 사용자에게 불리한 선정 방식

판정: `신청 가능`, `조건부`(확인할 항목을 적음), `부적격`(사유 한 줄)

## 출력

| 공고 | 기관 | 접수 기간 | 대상과 주택형 | 소득 기준 | 1차 판정 | 이유 |
|---|---|---|---|---|---|---|

- `신청 가능`과 `조건부`를 위에, `부적격`은 아래에 따로 모은다.
- 마감이 가까운 순서로 정렬한다.
- 끝에 자세히 볼 공고를 1~3개 추천하고, 사용자가 고르면 `housing-notice-analysis`로 넘긴다.
- 출처는 공식 공고 링크로 단다. 요약 사이트에서만 찾은 공고는 그렇다고 표시한다.
