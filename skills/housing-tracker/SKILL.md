# 신청 현황과 충돌 검사

## 데이터

- 파일: `$HOUSING_DATA_DIR/applications.md`, 기본값은 `~/.config/ai-public-housing-analysis/applications.md`
- **개인정보이므로 플러그인 저장소에는 절대 쓰지 않는다.**
- 파일이 없으면 아래 형식으로 만든다.

```markdown
# 신청 현황

| 공고 | 기관과 유형 | 신청 단위 | 순위 | 상태 | 다음 일정 | 메모 |
|---|---|---|---|---|---|---|
```

상태 값: `검토중` → `신청예정` → `신청완료` → `서류대상` 또는 `탈락` → `당첨` 또는 `예비` → `계약`. 중간에 `포기`, `부적격`, `비추천`으로 끝날 수 있다.

- 사용자가 실제 접수를 확인해 주기 전에는 `신청완료`로 바꾸지 않는다.
- 결정의 근거(공고 쪽수, 상담 답변, 사용자가 결정한 날짜)를 메모에 남긴다.

## 충돌 검사 (새 공고를 분석하거나 신청하기 전)

진행 중인 항목(`신청예정`부터 `계약`까지)과 새 공고를 비교한다.

1. **같은 유형 중복신청 제한**: 예를 들어 LH 청년 매입임대는 서류 제출까지 마치면 예비입주자 순번 발표 전까지 같은 유형의 다른 공고에 신청할 수 없다. 서류 제출 기간 안에는 취소할 수 있다.
2. **당첨자 발표일이 같은 주택**: 한 사람이 1건만 신청할 수 있는 공고가 있다.
3. **한 공고 안의 중복**: 1세대 1주택군(또는 1주택형) 규칙, 특별공급과 일반공급 중복 허용 여부
4. **재당첨 제한**: 분양가상한제 주택, 토지임대부, 분양전환 공공임대 등에 당첨되면 이후 청약이 제한된다. 당첨 뒤 계약을 포기해도 기록이 남는지 확인한다.
5. **공공임대 중복 입주**: 이미 공공임대에 살고 있다면 새 주택에 들어갈 때 기존 주택을 비워야 하는지 확인한다.

충돌이 있으면 결론보다 먼저 쓰고 공고 근거(쪽수, Q&A 번호)를 붙인다. 기관 사이(LH, SH, HUG)에도 적용되는지 불분명하면 "기관 확인 필요"라고 쓴다.

## 현황 조회

현황을 물으면 진행 중인 항목부터 보여 주고, **가장 가까운 다음 일정**을 첫 줄에 쓴다. 오늘이나 내일이 마감인 항목은 눈에 띄게 표시한다.
