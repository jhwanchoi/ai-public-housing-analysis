# 신청 현황·충돌 검사

## 데이터

- 파일: `$HOUSING_DATA_DIR/applications.md`, 기본값 `~/.config/ai-public-housing-analysis/applications.md`.
- **개인정보라 플러그인 저장소에 절대 쓰지 않는다.**
- 파일이 없으면 아래 형식으로 만든다.

```markdown
# 신청 현황

| 공고 | 기관·유형 | 신청 단위 | 순위 | 상태 | 다음 일정 | 메모 |
|---|---|---|---|---|---|---|
```

상태 값: `검토중` → `신청예정` → `신청완료` → `서류대상` / `탈락` → `당첨` / `예비` → `계약` / `포기` · `부적격` · `비추천`

- 사용자가 실제 접수를 확인해 주기 전에는 `신청완료`로 쓰지 않는다.
- 결정 근거(콜센터 답변, 사용자 결정 날짜)를 메모에 남긴다.

## 충돌 검사 (새 공고 분석 또는 신청 전)

진행 중인 항목(`신청예정`~`계약`)과 새 공고를 비교한다.

1. **같은 유형 중복신청 제한**: 예) LH 청년 매입임대는 서류제출까지 마치면 예비순번 발표 전까지 같은 유형 다른 공고 신청 불가. 서류제출 기간 안에는 취소 가능.
2. **당첨자 발표일이 같은 주택**: 1인 1건만 가능한 공고가 있다.
3. **공고 안 중복**: 1세대 1주택군·1주택형, 특공·일반 중복 허용 여부.
4. **재당첨제한**: 분양가상한제·토지임대부·분양전환 공공임대 등에 당첨되면 이후 신청이 막힌다. 당첨 시 포기해도 기록이 남는지 확인한다.
5. **공공임대 중복 입주**: 기존 공공임대 거주자는 새 주택 입주 시 명도 조건이 있는지 확인한다.

충돌이 있으면 결론보다 먼저 쓰고, 공고 근거(쪽수·Q&A 번호)를 붙인다. 기관 간(LH↔SH↔HUG) 적용 여부가 불명확하면 "기관 확인 필요"라고 쓴다.

## 조회 응답

사용자가 현황을 물으면 진행 중 항목을 먼저 보여주고, **가장 가까운 다음 일정**을 첫 줄에 쓴다. 마감이 오늘·내일인 항목은 강조한다.
