# 신청 준비

개인 데이터 위치는 `housing-notice-analysis`의 공통 규칙을 따른다.

## 캘린더 등록 (공고당 2개)

사용자가 요청했거나 지원하기로 정했을 때만 등록한다. 등록하기 전에 같은 공고 일정이 이미 있는지 검색해 중복을 피한다.

1. **청약 접수 첫날**
   - 시작 시각부터 그날 마감 시각까지 잡는다. 접수가 여러 날이어도 첫날만 등록한다.
   - 제목에 공고명, 신청 단위, 최종 마감 일시를 넣는다.
   - 알림: 하루 전, 1시간 전
2. **해당 신청의 서류 대상자 발표**, 발표 시각에 맞춰 등록
   - 서류 대상자 발표 없이 당첨자 발표 후 서류를 내는 공고라면 **당첨자 발표**로 등록하고, 메모에 그 점을 적는다.
   - 알림: 발표 시각

접수 첫날 일정의 메모에 넣을 내용:
- 공고명, 공고일, 주택관리번호, 신청 사이트
- 신청 내용: 공급유형, 순위, 지역 구분, 주택군이나 주택형
- **사용자 자격 판정 요약**: 항목별 기준과 사용자 값
- 신청하지 말아야 할 유형과 그 이유
- 보증금과 월세(분양이면 분양가와 토지임대료), 관리비 포함 여부
- 당첨 구조 요약, 당첨 시 주의사항(중복신청 제한, 재당첨 제한 등)
- 이후 일정(서류 제출, 계약, 입주)과 문의처

사용자가 메모 원문을 달라고 하면 캘린더를 다시 고치지 말고 **복사해서 쓸 수 있는 텍스트**로 준다. HTML 태그 없이 대괄호 소제목과 줄바꿈만 쓴다.

등록을 마치면 `housing-tracker`에 "신청예정"으로 기록한다.

## 기관 문의 문구

- 통화 중에 읽을 수 있도록 **짧게**, 질문을 하나씩 쓴다.
- 사용자가 원하지 않으면 개인 소득 금액은 넣지 않는다. 기준만 묻는 문장을 먼저 준다.
- 예상되는 답변에 맞춰 이어서 물을 질문을 한두 개 붙인다.
- 사용자가 통화 결과를 알려주면 출처(기관명, 날짜, 상담 답변임)를 붙여 기록하고 판정을 갱신한다. 상담 답변은 공고 문구보다 우선하지 않는다.
